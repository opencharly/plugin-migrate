# 2026.270.1351 — fix(migrate)!: ship a self-contained CUE schema (no schema-less plugin)

## Summary

Restore `plugin-migrate`'s **own self-contained CUE schema**. `NewMeta` passed a `nil` schema FS and served an **EMPTY** schema — the SDK's former *"input-less plugin"* waiver. There is no schema-less plugin: every plugin presents the same CUE-validated, code-generated surface, even where a capability's authored input is its pass-through CLI grammar rather than a structured `plugin_input`.

This is the **plugin-migrate leg** of the R5 cutover tracked in **opencharly/charly#712** (the sdk contract landed as **opencharly/sdk#314**).

### Files — 3 changed, +88 / −2

- `candy/plugin-migrate/schema/migrate.cue` — the plugin's OWN self-contained schema (`#MigratePlugin`), documenting the `command:migrate` contract. It references no base def and carries no package clause, so it compiles **standalone** and splices `base ++ plugin` at the host load gate (`registerPluginUnitSchema`). The comment now states the truth: NO Go consumer / no `cue exp gengotypes` artifact (the plugin declares no typed `plugin_input`), and the engine-internal `schema/migration.cue` is embedded separately by `engine.go` and deliberately NOT served.
- `candy/plugin-migrate/plugin.go` — `//go:embed schema/migrate.cue` + `sdk.NewMeta(calver, caps, schemaFS)` replaces the trailing `nil`; the stale schema-less comment is corrected.
- `candy/plugin-migrate/schema_serve_test.go` — `TestNewMetaServesNonEmptySchema` (the `Describe` reply MUST carry a non-empty, `#MigratePlugin`-bearing `schema_cue`) **and** `TestServedSchemaSplicesOntoHostBase`, which reproduces charly's real `compileBasePlusServed` splice (`registerPluginUnitSchema` → `base ++ plugin` compile) against the REAL `github.com/opencharly/spec/schema` base FS through the SAME `spec/schemaconcat` contract.
