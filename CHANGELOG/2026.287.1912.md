# 2026.287.1912 — feat(migrate): carry podman_jobs across the schema rename to stage_parallelism

## Summary

**The migration half of the build-engine cutover: ONE declarative table entry carrying `podman_jobs` / `podman_jobs_cap` across to `stage_parallelism` / `stage_parallelism_cap`.**

The build-speed INNER parallelism knob was named for the engine it was handed to (`podman build --jobs N`). With ONE image builder there is no second engine left to name, so the producer leg (`spec`, merged as `4e61d3d`, tagged `v0.2026287.1848`) renamed it and **closed** the old keys. A project still carrying them now fails the closed-CUE load, and the diagnostic points the reader at `charly migrate` — which is this entry.

**The knob SURVIVES rather than folding into `jobs:`.** `stage_parallelism` bounds the STAGES of a single build; `jobs` keeps its own name and bounds the OUTER dimension (images per DAG level). Two ops, not one, because the op-walker matches a key **exactly** — the same reason `k8s-to-kubernetes` above it needs two.

**Why this entry could only land AFTER the schema change:** an entry that rewrote users' configs to a key the closed schema had not yet accepted would make every migrated config **unloadable**. Producer-first is a loadability rule here, not a preference — which is why this PR is leg 2 and not part of leg 1.

**Not `touches_host`, measured rather than assumed:** the per-host overlay (`~/.config/charly/charly.yml`) is a `RuntimeConfig` — engine / run_mode / bind_address / encrypted_storage_path / volumes_path / secret_backend / forward_gpg_agent / forward_ssh_agent / vm / vnc_passwords / keyring_keys — and carries **no build defaults**, so no overlay can hold these keys. Marking the step host-touching would sweep nothing extra; it would only make remote-cache auto-migration **skip** it and leave every cached project document carrying the retired name.

Changed: **2 files, +145** — `candy/plugin-migrate/migrations.cue` (+25, the entry and its rationale) and `candy/plugin-migrate/engine_test.go` (+120, the three controls). One commit.
