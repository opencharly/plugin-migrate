# 2026.280.2238 — feat(migrate): retire a barren `group:` node — the per-host config that could not load (charly#827)

## Summary

Add the missing migration path for a **barren `group:` node**, so a config that cannot load becomes
loadable instead of looping the reader back to the command they just ran — `opencharly/charly#827`.

`group:` was the targetless group kind Cutover C retired. `unroll-group-deploy` reshapes it by
promoting its FIRST MEMBER into the primary kind, and it deliberately leaves a DEGENERATE group to
the load-time gate. For an EMPTY group that gate can never clear: the node carries no kind
discriminator, the whole document hard-fails, and the message says `run: charly migrate` — the
command that just walked past the node. Because the per-host overlay is read for every `kind: vm`
command, one leftover node makes **every VM bed on that host unbootable**:

```
$ python3 -c "import yaml;d=yaml.safe_load(open('/home/atrawog/.config/charly/charly.yml'));print(list(d.keys()))"
['cache', 'ledger', 'check-dsh-pod']
$ charly vm create eval-host-vm
Warning: vm config-resolve: per-host deploy overlay unavailable for read: load deploy config via executor: /home/atrawog/.config/charly/charly.yml:doc0: node "check-dsh-pod": no kind discriminator — collections and plan steps live INLINE in the kind value (the named child-node shape was removed); run: charly migrate
charly: error: command "vm": persisting auto-allocated ports: reading charly.yml for update: load deploy config via executor: /home/atrawog/.config/charly/charly.yml:doc0: node "check-dsh-pod": no kind discriminator — collections and plan steps live INLINE in the kind value (the named child-node shape was removed); run: charly migrate
```

**The change.** One new table entry, `retire-empty-group-node` (`touches_host: true`,
`apply: "retireEmptyGroupNode"`), appended last so it runs AFTER `unroll-group-deploy`: a group WITH
a member is reshaped into its primary first, and only what is left barren is retired. The predicate
is deliberately narrow — an entry whose value has a mapping-valued `group:` and **no other
mapping-valued child**. A group whose first member merely lacks a kind word, and any node carrying
another unknown key, are left exactly as before, so the hook never guesses and never drops authored
content; a barren group's own scalars go with it, which the hook's doc and the table entry both
state, because a group with no member describes no workload. None of the four declarative ops can
express a predicate-keyed ENTRY deletion (the entry's name is authored, not derivable), which is
why this is an `apply:` hook.

Closes `opencharly/charly#827`.
