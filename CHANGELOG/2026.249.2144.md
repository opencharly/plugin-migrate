# 2026.249.2144 — migrate: recognize in-substrate members when unrolling a group: node (R1 follow-up to #6)

## Summary

Follow-up to #6 (R1 from the charly-wave dogfooding): the `unrollGroupDeploy` hook refused — and would have mis-promoted — a group member carrying an **IN-SUBSTRATE nested member** (the `check-group` corpus shape: a `vm:` member nesting a `local:` deploy inside the member node). The charly tree's live dogfood (Cutover C task 1, charly half) hit exactly this: `check-group-vm`'s value carries BOTH the `vm:` discriminator AND the nested `check-group-member:` key.

Two changes, both proven by the corpus shape:

1. **Frozen-vocabulary discriminator** — the member's kind discriminator is recognized as the ONE mapping-valued key whose word is in `frozenSubstrateWords` (`pod/vm/kubernetes/local/android` + the retired `k8s` spelling, renamed before this row by k8s-to-kubernetes, kept so arbitrarily old configs reshape cleanly). The former shape-only rule (exactly one mapping-valued key) misread any in-substrate member as ambiguous and refused it.
2. **Whole-value promotion** — the member's ENTIRE value promotes (the kind pair plus any in-substrate nested-member pairs stay INSIDE the promoted node). The former code promoted only the kind pair and would have DROPPED the nested member — data loss.

The conservative refusal paths are unchanged (no promotable member / zero or two kind words → untouched, the load gate names the node).

**On R3 — why `frozenSubstrateWords` is NOT a duplicate of `reshapeKindWords`:** `reshapeKindWords` (reshape_compact.go) classifies TOP-LEVEL node-kind words and deliberately includes `group`, `candy`, `fleet`, `check`, `distro`, `builder`, `agent`, `sidecar`, `resource`, `init` + the retired Calamares words. This hook answers a DIFFERENT question — which key INSIDE a member value is the substrate discriminator. Reusing `reshapeKindWords` would be a BUG: a nested `group:` (a legitimate in-member shape this very hook rewrites recursively) and non-substrate kinds would be picked as the discriminator. The two frozen vocabularies own two different behaviors; both are frozen literals because migrations replay against arbitrarily old configs and must never read the live registry (the frozen-snapshot doctrine). The new set is documented as such at its declaration.
