# 2026.332.0323 — feat(migrations): remap the retired git-submodules mode bump to ff

## Summary

Appends ONE idempotent migration step to the table: `git-submodules: {mode: bump}` → `{mode: ff}`, and adds the step's live proof to the disposable bed.

`verb:git-submodules`'s advance mode `bump` became `ff` and the old word is refused by the plugin's schema (`opencharly/plugin-task#69`), so every authored project that composes the advance has to be reshaped. The rewrite is **path-scoped** — a `mode:` that is a DIRECT child of a `git-submodules:` mapping — which is why it is an `apply:` hook (`remapGitSubmodulesMode`) and not a declarative `remap_scalar`: the op vocabulary has no parent-path predicate, and a document-wide `mode: bump` remap rewrites an unrelated scalar that happens to spell the retired word (spiked below). It is the same shape as the existing `remapEngineRunWord` (`engine: {run: nerdctl}`), deliberately.

### Spike

Fixture carries BOTH scalars: a `git-submodules: {mode: bump}` step and an unrelated `tool: {mode: bump}` step.

**Candidate A — declarative `remap_scalar {key: "mode", from: "bump", to: "ff"}`, via the engine's OWN op-application path** (`applyOp` → `opTargetMappings` default `scope: any` → `allMappings` → `remapScalarDirectChild`), in a throwaway `_test.go`:

```

    zz_r12_spike_test.go:65: applyOp(remap_scalar mode bump->ff, scope=any) changed=true
        --- document after ---
                    - run: advance every pin
                      git-submodules:
                        mode: ff              <- wanted
                    - run: an unrelated tool mode that happens to spell the retired word
                      tool:
                        mode: ff              <- CORRUPTED
--- PASS: TestSpikeR12CandidateA_DocumentWideRemapScalar (0.00s)
```

**Candidate B — the path-scoped `apply:` hook**, driven through the rebuilt binary on the identical fixture:

```
$ /tmp/ff-spike/bin/charly-migrate migrate --dir /tmp/ff-spike/mig-fixture --project-only
applied git-submodules-mode-ff
migrated
migrate-exit=0

--- after ---
              git-submodules:
                mode: ff                  <- rewritten
            - run: an unrelated tool mode that happens to spell the retired word
              tool:
                mode: bump                <- untouched

$ … migrate --dir … --project-only      # second run
nothing to migrate
second-exit=0
```

**Verdict: A fails** (it corrupts an unrelated field), **B wins.** Why no parent-path predicate exists: `#RemapScalar` has no `scope` field at all, its only discriminator `under_kind` selects an entity KIND discriminator (`candy:`/`box:`/`deploy:`) which a plan step inside a `task:` does not carry, and `move_key`'s `from_parent`/`to_parent` is a reparent, not a conditional predicate. The spike instrument was deleted (`git status` clean afterwards).
