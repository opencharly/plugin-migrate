# 2026.276.1504 — fix(migrate): never strip a top-level `version:` from a non-manifest YAML (#16)

## Summary

`charly migrate`'s universal `strip-version-stamp` step **deleted the top-level `version:` key from non-charly YAML**. The candidate sweep (`kit.OpUnifyCandidateFiles` → `MigrateCandidateYAMLFiles(dir, {candy, box})`) covers every root-level `*.yml`/`*.yaml` sibling plus the `candy/` + `box/` trees, and `stripVersionField` deleted the first top-level `version:` line of any file it was handed. A top-level `version:` is a charly SCHEMA stamp **only in a `charly.yml`** — but on this host `charly migrate` stripped `version: "2"` from the tracked **`.golangci.yml`** (golangci-lint's config-schema version), silently corrupting a non-charly config.

## Root cause

`stripVersionStamp` (`candy/plugin-migrate/engine.go`) sweeps `spec.UnifiedFileName` plus `kit.OpUnifyCandidateFiles(ctx.Dir)` and calls `stripVersionField` on each. `stripVersionField` had no manifest check; any candidate YAML with a top-level `version:` was treated as a charly stamp. `.golangci.yml` is a root-level `.yml` sibling, so it matched.

## Change

- `engine.go` — `stripVersionField` now returns early unless `filepath.Base(path) == spec.UnifiedFileName`. Every legitimate stamp is a `charly.yml` (root, `candy/<n>/charly.yml`, `box/<n>/charly.yml`, imported manifests are all named `charly.yml`), so all real stamps are still stripped; the per-host `~/.config/charly/charly.yml` is stripped by its own explicit call site (basename `charly.yml`).
- `engine_test.go` — `TestRunMigrations_LeavesNonManifestVersionAlone`.
