# 2026.270.1917 — fix(migrate)!: strip the top-level version stamp from every candidate doc

## Summary

Fix a gap in the versionless migration engine: the universal `strip-version-stamp` step removed the top-level `version:` from the root `charly.yml` (`universalStampFiles = [spec.UnifiedFileName]`) and the per-entity stamp from candy/box bodies, but **missed the top-level stamp on every NON-root project document** — `candy/<name>/charly.yml` and `box/<name>/charly.yml`.

That is not cosmetic: the **remote-cache auto-migration** runs this step on every freshly-fetched remote repo. A stamped candy manifest therefore survived migration, and the importing host's `#NodeDoc` load gate rejected the whole import:

```
charly: error: … import cachyos ("@github.com/opencharly/distro-cachyos:v2026.269.2233"): …/candy/crabbox-nesting-dns/charly.yml: node "version": #NodeDoc.version: conflicting values "2026.240.1943" and {...}
```

This blocks the charly host leg's assembled `disposable: true` bed (opencharly/charly#714) and would block every consumer that imports a stamped candy repo.

**Fix.** After the `universalStampFiles` loop, sweep every `kit.OpUnifyCandidateFiles(ctx.Dir)` document's top-level stamp with the same `stripVersionField` (idempotent — a file with no top-level stamp is untouched, so re-visiting the root is a no-op).

```
 candy/plugin-migrate/engine.go      | +15
 candy/plugin-migrate/engine_test.go | +36
```
