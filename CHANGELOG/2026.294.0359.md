# 2026.294.0359 — fix(migrate): emit the plan shape the pipeline loader accepts (intent label + #TaskParamSpec-valid args)

## Summary

`reshapePipelineVerbStage` emitted a lifted verb stage as **bare step-level sugar** — `plan: [{agent: {…}}]` — which `#Step`'s closed intent disjunction rejects with `plan[0] has no intent keyword (run/check/agent-run/agent-check/include)`. Every migrated config carrying an `agent` / `probe` / `ade` / `generate` / `emit` / `media` / `gate` stage was therefore **unloadable**: **12 such steps** in the org's only real consumer, `opencharly/eval-omarchy`. `reshapePipelineEnsureArg` emitted a second, independent load failure: `args.<name>.type: string`, which `#TaskParamSpec` (description/default/required) rejects as `field not allowed`.

Both are `opencharly/plugin-migrate#20`. This fixes the two emitted-shape defects **and the missed control that let them ship**.

- **The lifted-verb step now opens with the `run:` intent keyword and the stage's own `id:` as its label**, with the verb key kept beside it (`- run: oracle` + `agent: {…}`). `run` is not a per-kind semantic verdict — plugin-pipeline's own bed spells every lifted verb that way (its `gate:` step is `- run: grade the build result` + `gate: {…}`, `plugin-pipeline/charly.yml:254-258`) and states the rule outright at `:298-303`: *"a lifted verb is spelled as a plan step carrying an intent label AND the verb key … never as bare step-level sugar."* The label is the `id:` the author already wrote (verb word as fallback when a stage has none), so nothing invented enters the config.
- **`args:` entries carry only `description:`**, and its text now names the surface that actually binds the value (`--args-json`) instead of the retired `--prs`, which no binary has had since `plugin-pipeline#32` deleted the batch-lane surface.
- **The load-gate control is added** (`TestPipelineLobsterEmittedShapeIsLoadable`): it asks the *loader's* question of the migrated document — exactly one intent keyword per `plan:` element from the closed `spec.StepKeywords` set, exactly one verb key beside it, and only `#TaskParamSpec` fields under `args:` — instead of grepping the emitted text. That is precisely why the defect survived: the old fixture *pinned the unloadable shape as the expected one* (`reshape_pipeline_lobster_test.go:208` asserted `"- agent:"`), and the `check-migrate-local` bed asserted the same text (`charly.yml`, `migrate-pipeline-v1`: `grep -qE "^[[:space:]]+- agent:$"`).

Scope note, stated plainly: **this does not make `eval-omarchy` load.** With this fix the two named errors are gone and the next failure is a different one — that repo pins `plugin-pipeline:v2026.272.0332` (its `eval-pr` candy manifest, line 35), the retired executor whose `OpValidate` still demands `stages:`. Bumping that pin is a consumer change entangled with the lane decision (`plugin-pipeline#43`), and past it two further gaps appear that are **grammar** limits rather than reshape bugs — filed as `opencharly/sdk#437`.

### Round 2 — the round-1 BLOCK, fixed

Round 1 blocked on **R2, correctly**: the new control declared its *own* copy of the frozen intent vocabulary and re-derived the intent/verb split inline, so the file held two copies of one closed set and two parsers of one element shape — while this body claimed the opposite. The claim is now true rather than reworded:

- `pipelinePlanIntents` is the file's one vocabulary;
- `pipelinePlanVerb` is the one splitter, returning a `pipelinePlanElement` (intent count, the single verb key, its body, and every non-intent key it saw, so a diagnostic can name them) with a `wellFormed()` predicate;
- all five readers go through them: the knob self-containment walker, the verb-body lookup, the per-kind coverage guard, and the load-gate control.

**RCA / missed control:** I asserted R2 compliance from intent instead of from the diff. The control that catches this class is a one-line count on the tree — the vocabulary literal must appear exactly once — so that count is now pasted below as evidence, not described.
