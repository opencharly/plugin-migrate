# 2026.295.1526 — feat(migrate): rewrite the retired engine word nerdctl to containerd

## Summary

`opencharly/spec` v0.2026295.1243 (spec#266) deleted `nerdctl` from `#EngineName` — the closed vocabulary is now `podman | docker | containerd`, and `#EngineBinaries` maps the WORD `containerd` to the CLI binary `nerdctl`. `charly migrate` is served by THIS repo (`command:migrate`) and had no entry for the retired word, so an existing config had no documented path forward (R5 left half-done; tracked as #25).

Two authored surfaces, two shapes:

| Surface | Authored shape | Mechanism |
|---|---|---|
| Project (`#Deploy` / `#Candy` / `#Kindcluster`) | `engine: nerdctl` (scalar) | declarative step `engine-word-containerd`: one `remap_scalar` `engine: nerdctl → containerd`, whole document |
| Host runtime config (`~/.config/charly/config.yml`, `hostenv.RuntimeConfig`) | `engine: {run: nerdctl}` (mapping) | `apply:` hook `remapEngineRunWord`, `touches_host: true`, `host_config: "runtime_config"` |

**Why the host arm needed more than a hook.** The engine's only host surface was `HostDeployPath` — `~/.config/charly/charly.yml`, whose type `spec.DeployConfig` has **no engine field** (only `provides`/`deploy`/`sidecar`/`cache`/`ledger`/`system`). The runtime engine is in a DIFFERENT file, `hostenv.RuntimeConfigPath()` → `~/.config/charly/config.yml`. A hook run against the old overlay surface would have been a no-op in reality (the pre-change CLI arm below proves it: the old binary reports `nothing to migrate` and leaves `config.yml` carrying `run: nerdctl`).

**Why a hook, not an op.** The op vocabulary has no parent-path predicate: `remap_scalar` keyed on `run` cannot require it to sit under `engine:`, and a document-wide remap would rewrite an unrelated `run: nerdctl` scalar. `remapEngineRunWord` rewrites only a DIRECT `run:` child of an `engine:` mapping, and is idempotent. The declarative `remap_scalar` arm and the hook now share the ONE implementation `remapScalarDirectChild` (R2).

**The host-surface selector.** `#Migration` gains `host_config?: *"overlay" | "runtime_config"`, so a `touches_host` step names exactly ONE per-host file. Every pre-existing host step defaults to `overlay` and is unchanged. The selector is load-bearing: if every host step ran against `config.yml`, `reshapeDeployCPU` would rename the LIVE `RuntimeVmConfig.cpus` field to `cpu`. `TestRunMigrations_HostConfigSelectsOneSurface` pins the routing and keeps `vm.cpus: 4` intact.

**Pins.** `spec v0.2026295.1243`, `sdk v0.2026295.1359`. The older sdk does not compile against the new spec, and sdk's own `go` directive raises this module to `go 1.26.8`.
