# 2026.326.1527 — test(bed): pin the pipeline fixture to a release the current spec can load

## Summary

`charly migrate` removes `aur` from every box `build:` list (opencharly/sdk#608). spec#420 made `aur` a manager declaration, never an OS package format, so a box carrying `build: [pac, aur]` is refused by the schema; this step repairs it.

- A new declarative op, `remove_list_value {key, value, under_kind?}`: it removes every scalar `value` from a direct child key's list. A list the removal empties — or a key whose scalar is exactly `value` — loses the key, with its head comment carried over, so the field falls back to its default. It is idempotent, and it never touches a `build: all` run verb or a candy's `distro.<tag>.aur` declaration, because it matches the VALUE and only at a direct child key.
- The `aur-not-a-build-format` step uses it with `{key: build, value: aur}`. It is a pure PROJECT step: no host touch, no hook.

**The bed is green on this head and now exercises this step.** `check-migrate-local` gained two arms — `migrate-aur-build-list` (the refused `build: [pac, aur]` config, alongside a `build: all` run verb and a `distro.arch.aur` declaration that must survive, plus the `[pac]` result) and `migrate-aur-build-list-idempotent` — so the bed fails without the step instead of asserting the engine's coverage in prose. The negative control it previously failed is still what makes it meaningful: the fixture pins `plugin-pipeline:v2026.324.0037`, the release the current spec can load, so `box validate` rejects the retired `concurrency:` grammar again (`#PipelineValue.concurrency: field not allowed`) instead of skipping the pipeline candy and passing. opencharly/plugin-migrate#33 is fixed by that pin.
